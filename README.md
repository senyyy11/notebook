# 个人学习笔记库写作规范

本仓库用于保存经讨论、理解和整理后的学习笔记，尤其是论文阅读笔记。笔记应兼具论文的严谨性与博客的可读性：准确、可追溯、结构清晰，并能够在日后独立阅读和复习。

## 工作方式

- 你提供论文、资料或学习主题；我负责解析、讲解，并围绕你的问题展开讨论。
- 只有在你明确提出“整理成笔记”“保存笔记”或同等要求时，才创建或修改笔记。
- 在每次创建或修改笔记前，只读取一次本 `README.md` 以遵守规范；不扫描、阅读或改动其他笔记，除非你明确指定文件。
- 笔记以原始资料和我们已经完成的讨论为依据。无法从资料或讨论中确认的内容应明确标为推测、待验证或待讨论，不写成既定结论。
- 不自动联网检索、下载资料、批量创建目录或批量修改笔记；但在正在编写的笔记确实需要配图时，可按本规范选择和保存图片。其他联网或批量操作仍需要你的明确要求。

## 文件与资源组织

- 每个主题或每篇论文独立保存为一个 Markdown 文件，使用清晰、稳定的中文文件名。
- 图片、图表、论文式结构图及其他二进制资源统一放在 `assets/` 下，不直接放在笔记根目录。
- 每篇笔记的资源放在独立子目录中：`assets/<简短英文标识>/`，以避免不同笔记的图片混杂。资源目录名和图片文件名只使用英文字母、数字、连字符或下划线，不使用空格、中文或其他特殊字符，以兼容 Obsidian、GitHub 和标准 Markdown。
- 除非你明确要求，不为纯文本笔记创建空资源目录。
- 图片文件优先使用 `.png`；照片或连续色调图像可使用 `.jpg`。文件名使用简短英文描述用途，例如 `architecture.png`、`figure-3-training-flow.png`。

## 图片与图表规范

- 图片服务于理解，不作为装饰。对论文方法、模型结构、实验结果或关键直觉，优先采用能清楚表达信息的 PNG/JPG 图；Mermaid 仅作为简单关系图或需要后续频繁编辑时的可选方案。
- 图片可按以下优先级选用：原始论文中的图、具备明确可复用许可的网络图片、为本笔记生成的示意图。应根据表达效果选择，而不是默认使用 Mermaid。
- 使用论文原图时，保留其图号和含义，并在图注中标注“来源：原论文 Figure X”。若论文有公开链接或 DOI，一并提供链接。
- 使用网络图片或截图时，只选用版权状态和复用许可明确、适合在公开 GitHub 仓库保存的资源；图注中注明来源页面、作者/机构（如有）和许可信息。无法确认复用许可时，不将图片下载或提交到仓库。
- 生成的示意图应忠实反映资料和讨论内容，不得伪装成论文原图或实验结果；图注标注“AI 生成示意图”，并说明其解释目的。
- 每张非装饰性图片均应有相邻图注，说明图中对象、阅读重点与来源。若图来自论文，应区分“原图展示的事实”和“本笔记对图的解读”。
- 图片保存到对应的 `assets/<简短英文标识>/` 目录，并使用不含空格的相对路径嵌入 Markdown，使 Obsidian 与 GitHub 均能加载。

## 笔记写作要求

- 行文采用“论文 × 技术博客”的风格：概念与结论严谨，叙述则尽量直观、连贯，帮助未来的自己快速重建理解。
- 每篇论文笔记通常包含：
  1. 题目与资料信息；
  2. 要解决的问题与研究背景；
  3. 核心观点或整体方法；
  4. 方法细节、实验或论证；
  5. 关键结果与结论；
  6. 重要概念、难点及我们讨论后的理解；
  7. 局限性、假设条件、未解决问题或待进一步讨论的内容。
- 不必机械套用上述章节；结构应服从资料本身和讨论重点。非论文主题可采用同样严谨、便于复习的组织方式。
- 重要定义、损失函数、目标函数、推导关系和关键计算应使用 LaTeX 数学公式书写；公式需说明符号含义、适用条件及其在论证中的作用，不能只罗列公式。

### 公式兼容规范

笔记需要同时在 Obsidian 和 GitHub Markdown 页面中正确显示。公式只使用以下两种分隔形式：

- 行内公式使用 `$...$`，例如：梯度为 $\nabla_\theta \mathcal{L}(\theta)$。
- 独立公式使用单独成行的 `$$` 包裹，并在公式前后各留一个空行，例如：

  $$
  \mathcal{L} = -\sum_{i=1}^{N} y_i \log p_i
  $$

- 不使用 `\(...\)`、`\[...\]`、HTML/Markdown 混合标签或其他公式插件专用语法。
- 不在普通 Markdown 代码块中书写需要渲染的公式；公式中出现的美元符号需写为 `\$`。
- 避免依赖自定义宏、外部 LaTeX 包或渲染器特有命令。GitHub 不允许 `\operatorname{...}`；需要直立显示函数名时统一使用 `\mathrm{...}`。若 GitHub 的 MathJax 无法支持某个复杂公式，应将公式拆为基础 LaTeX 表达式，而不是牺牲 GitHub 可读性。
- 写入或修改笔记后，应检查每个公式都使用上述分隔符，且块公式的 `$$` 独占一行。
- 对具有模块、层次、并行分支、数据流、反馈回路或训练/推理差异的内容，应提供结构图。结构图应表达论文中的真实组件关系、输入输出、连接方向和关键操作，而非仅列出章节或线性步骤。
- 结构图应优先选择最适合信息密度的形式：复杂架构、原论文图和正式示意图使用 PNG/JPG；简单且需要可编辑的关系图可使用 Mermaid。无论形式如何，都必须说明它表达的对象和阅读要点。
- 区分原文事实、作者主张、实验结果与我们的理解/评价；必要时使用明确的小节或标注。
- 临时猜测、未经讨论确认的草稿想法不自动写入正式笔记。

## 修改原则

- 修改已有笔记时，只处理你指定的文件及其对应资源目录。
- 保留已有的有效内容；若新的理解修正了旧结论，应更新相关段落，使笔记内部保持一致，而不是仅追加相互矛盾的内容。
- 完成写入后，检查 Markdown 链接、公式分隔符、图片路径和结构图语法，确保在 Obsidian 中可正常阅读。
